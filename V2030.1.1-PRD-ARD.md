# affidavit v2030.1.1 — PRD / ARD

**Release:** Chatman Ecosystem v2030.1.1

## Product requirement

`affidavit` SHALL be the small provenance and certification kernel that turns bounded evidence into sealed, independently verifiable receipts. Its v2030.1.1 mission remains **certify, don't decide**: it carries identity, provenance, consequence, verification, replay, and standing evidence without becoming a planner, policy engine, or production actuator.

## Required capabilities

1. Represent exact subject identity for source trees, semantic graphs, generated artifacts, executions, deployments, marketplace events, and other ecosystem evidence.
2. Construct content-addressed receipts over canonical stable bytes, preferring BLAKE3 under current ecosystem policy.
3. Represent provenance edges between observation, admission, construction, execution, verification, and replay.
4. Make `ALIVE` structurally dependent on the evidence classes required by the owning claim rather than a manually written status field.
5. Validate receipt chains/DAGs, tamper resistance, and replay witnesses.
6. Preserve ERRC and other bounded transformation receipts without promoting correlation/measurement into causality, optimality, or authority.
7. Support export into PROV-O/semantic evidence representations where applicable.
8. Keep dependency stubs/fences explicit: a referenced upstream capability is not proof that upstream executed.

## Architecture requirements

```text
bounded claim + exact subject
      -> evidence inputs
      -> canonical receipt payload
      -> cryptographic identity
      -> verifier
      -> receipt DAG edge
      -> replay/tamper court
```

A receipt object has no standing merely because it is named `receipt`. The canonical verifier must accept it. Receipt construction carries no ambient policy or actuation authority.

## Acceptance for v2030.1.1

- receipts bind exact subject, actor/tool, authority class where relevant, requested/actual consequence, pre/post state evidence, verification, environment/toolchain identity, and replay information;
- tampering with any identity-bearing field invalidates verification;
- receipt DAG traversal can explain how an ecosystem claim was manufactured from prior evidence;
- replay status distinguishes deterministic, bounded-nondeterministic, externally dependent, and non-replayable operations;
- representative source/build/test/deploy/marketplace/actuation evidence can compose without claiming edges that were never observed;
- downstream systems can verify receipts without trusting narrative summaries.

## Falsifiers

The architecture is falsified if arbitrary JSON can self-certify; if a receipt cannot identify the exact subject it refers to; if a certificate decides policy or authorizes execution; if replay identity omits materially outcome-affecting configuration; or if upstream stubs are treated as executed capabilities.

## Ecosystem contract

`affidavit` certifies evidence. It does not select architectures, grant authority, or perform production DO. MFW/AutoFDE/runtime systems produce consequences; Affidavit makes those consequences auditable and composable as evidence.
